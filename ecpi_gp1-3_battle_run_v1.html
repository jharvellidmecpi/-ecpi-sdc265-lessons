1.3 Guided Practice: Battle Run

Review: What Makes a Strong Algorithm?

An algorithm is a set of instructions. A plain-language algorithm describes how to solve a problem using ordinary words. A battle run is one sequence in which two characters take turns attacking until one wins.

A good algorithm is…

  • Ordered: the steps happen in a clear sequence.
  • Specific: each step says exactly what should happen.
  • Repeatable: someone else could follow it and get the same kind of result.
  • Conditional: some steps depend on what happens, like whether a character is still alive.
  • Complete: it has a clear beginning, middle, and end.

Weak algorithm

“The hero fights the monster. They attack each other until someone wins.”

That’s too vague. Who attacks first? How is damage calculated? When is health checked? When does it end? It could run forever, and the cloud bill would come every month.

Strong algorithm

For each step, choose the label that fits best: Ordered, Conditional, or Repeated. You’ll get feedback right away.

Examine the difference

The strong algorithm meets all five qualities. You know who attacks first, how health drops, when defeat is checked, and when the battle stops. You just follow the steps until someone runs out of health.

Push your thinking: Which steps are Boolean logic? Which are repetition? Which are conditions? Use the Strong algorithm tab to explore.
